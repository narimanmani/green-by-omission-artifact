SP2027 · DEFENSIVE RTS RESEARCH · 10 NOVEMBER 2026

Regression test selection under controlled metadata-integrity faults

Measured native behavior, synthetic library feasibility, and a reproducible configuration audit

Main finding

No relevant-test omission was observed in completed runs, and no changed-source comparison returned a passing result. The study contains 189 analyzed local runner invocations: 162 changed-source comparisons and 27 controls or supplemental integration checks. Of the comparisons, 156 completed with the intended assertion failures; six testmon invocations stopped with explicit database errors. Those errors are not selection omissions or passing builds.

The positive defense result is narrower: a trusted-manifest check detected the deliberately injected metadata faults and invoked an agent-free full suite. For testmon's two corrupted-database conditions, this recovered executable regression evidence from otherwise aborted runs. Standard Ekstazi already detected every seeded regression in this corpus, so these data show no incremental defect-detection benefit from the guard for Ekstazi.

1. Questions and scope

The experiment asks whether cold/warm selection works, whether ordinary harmless regressions are detected, how the native selectors respond to fixed integrity faults, and what a fail-closed check changes. It does not test an adversary's ability to reach, replace, or exploit a real CI cache.

All dynamic subjects were locally generated synthetic applications and test fixtures. Five fixtures call unmodified published Java libraries. No upstream source, remote repository, production system, or CI workflow was modified. Dependencies and public repository snapshots were downloaded during preparation; actual fixture executions perform no network I/O. Isolation means separate local workspaces and processes, not a claimed container or enforced network namespace.

The same unchanged tests act as the oracle across arms. A +1 arithmetic change intentionally violates two assertions in the Java/Python toy programs. Java library wrappers append a harmless exclamation mark to a returned value, violating one synthetic assertion. An independently changed module retains its correct output, ensuring a passing changed control is available, while another module stays untouched.

3. Paired experiment design

Each condition starts from the same warmed baseline restored at the same absolute path. This avoids accidental invalidation from relocated dependency paths. Full-suite arms run without the selector and receive their own restored state, preventing them from repairing metadata used by an RTS arm. Before and after hashes, test identities, actual process exits, native logs, JUnit observations, and test source hashes are retained.

The Ekstazi matrix has eight fixed conditions × three strategies × three technical repetitions: 72 comparisons. Faults include a missing or empty target dependency record, retaining the first floor(n/2) bytes, an invalid header, deleting the cache, adding an unexpected file, and supplying a wrong synthetic baseline label. The fraction is fixed; no adaptive byte search or fingerprint manipulation occurred. The baseline-label condition changes only the guard's declared provenance value; it is not evidence about restoring an actual older cache.

For native Ekstazi, a frozen seed shuffles condition/strategy order within each repetition. Testmon and wrapper ordering is fixed and disclosed. Testmon has five cache conditions × three strategies × three repetitions. Each library wrapper has three conditions × three strategies, with one observation per cell. These are designed case studies, not random samples of faults or deployments.

8. Defense interpretation

The research guard compares a separately trusted SHA-256 manifest with the complete observed cache inventory. Native Ekstazi additionally binds the test source inventory, exact agent binary, and a synthetic expected baseline ID. Testmon checks cache bytes and test inventory. Library wrappers check cache inventory while separately verifying unchanged test source/bytecode. These are related guard prototypes, not identical fully authenticated CI systems.

On rejection, the driver executes the full suite with the selector disabled. A successful manifest comparison only shows agreement with a trusted snapshot. It does not prove that the original graph was complete, that cache generation was correct, that a baseline matches real repository history, or that the manifest itself cannot be replaced. No signing service, immutable remote cache policy, complete JDK/build provenance chain, or race-free verification/use boundary was implemented.

In this finite corpus, the guard provides integrity rejection and deterministic fallback. It does not improve Ekstazi's detected-regression count because the unguarded tool already detects every seeded regression. For testmon's corrupt-database cases, the benefit is recovering an executable diagnostic path; the unguarded process already failed and did not accept the regression.

9. Descriptive statistical analysis

The descriptive analysis unit is the designed fixture/condition, not each repeated invocation. Native Ekstazi and testmon repetitions verify repeatability. All 24 Ekstazi condition/strategy cells and all 15 testmon cells have identical discrete outcomes across their three repetitions. Five wrappers share one harness pattern and have only one observation per cell. Counting these as independent security trials would exaggerate evidence.

The report therefore provides counts, denominators, selected-test fractions, matched outcomes, and per-cell median/minimum/maximum wall times. It provides no p-values, attack-success confidence intervals, rule-of-three bounds, or population prevalence interval. The 162 comparison rows are an audit count, not a sample-size claim supporting general security rates.

10. Validity threats and untested hypotheses

  • Construct validity: harmless output regressions demonstrate detection behavior; they are not actual exploitable security defects. Generic damage does not cover every valid-but-incomplete dependency graph.
  • External validity: one small arithmetic fixture per language, five closely related wrapper fixtures, one Java/JUnit configuration, one Python configuration, and a single-organization static sample.
  • Mechanism coverage: native cache deletion, emptiness, truncation and malformed input were tested. Actual stale-cache restoration, graph completeness, selector concurrency, dynamically generated code, broad reflection patterns, and hosted cache permissions were not established.
  • Internal validity: path-stable state restoration, independent full-suite arms, unchanged test hashes, fresh logs, and exact test identities reduce contamination. Setup attempts and the first harness directory-creation error are retained separately and excluded from the formal matrix.
  • Defense assumptions: the manifest is protected from the injected faults. No proof is made for a setting where both cache and manifest are replaceable, or where metadata changes between verification and use.
  • Statistical validity: deterministic repeats and purposive samples do not justify inference to all faults or deployments. Timing reflects concurrent local activity.
  • Unconfirmed hypotheses: other integrity faults might omit relevant tests; deployed CI might restore untrusted metadata; stronger provenance controls might reduce failures in a broader corpus. None is established by these measurements.

For an S&P submission, these results support a reproducible defensive robustness pilot and negative findings for the tested faults. They do not support a claim that Ekstazi was bypassed or that an exploitable RTS vulnerability is prevalent. A defensible next extension would independently define broader non-adaptive fault classes, retain all negative outcomes, validate genuine larger suites under an explicitly expanded scope, and sample deployment configurations from a justified frame.
