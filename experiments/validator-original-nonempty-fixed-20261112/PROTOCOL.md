# Fixed original-test nonempty Ekstazi experiment

Frozen before the first candidate execution on 12 November 2026. The machine-readable manifest is `input/FROZEN_MANIFEST.json`; it pins the exact source/test hashes, archived collision bytes, and one control edit. One case is evaluated in three fresh containers. Every repetition and failure is retained. No candidate search, source retuning, modified tests, altered selector, or result-dependent revision is permitted.

Subject: original Apache Commons Validator 1.7, commit `f9bb21748a9f9c50fbc31862de25ed49433ecc88`. The unchanged upstream oracle consists of exactly `UrlValidatorTest`, `RegexValidatorTest`, and `CreditCardValidatorTest` under one integrated Maven/Ekstazi POM. The POM adds the third original test class to the previously retained integration; all upstream test sources remain byte-identical. This is a defined three-class oracle, not the full Commons Validator suite.

Candidate: the previously archived CRC32-preserving `UrlValidator.java` source, copied byte-for-byte from the earlier fixed experiment, plus one benign expression change in `CreditCardValidator.java`: for a null or empty card, `return false;` becomes `return Boolean.FALSE.booleanValue();`. This second change is fixed before outcomes to select original credit-card tests while keeping the URL scheme regression and original URL security assertions unchanged. No other production path changes.

For each fresh repetition, execute the original three-class baseline with native Ekstazi 5.3.0, verify all original tests pass, save trusted metadata, and verify an unchanged rerun selects zero tests. Apply the fixed candidate once. Recompile and require the `UrlValidator.class` SHA-256 to match the archived collision class and the native Ekstazi fingerprint to equal the baseline value `577934113`. Require the credit-card class to change. Restore baseline metadata, run native selection, then run the complete same candidate oracle without the Ekstazi profile in an independent clean copy. Verify candidate/test/config hashes before and after each arm. Record actual Surefire calls, exits, failures, and selected/omitted IDs.

Stop before candidate test execution on baseline failure, absent unchanged deselection, missing dependency, build/toolchain error, source identity drift, or fingerprint mismatch. Native detection, empty selection, nonempty false pass, and full-oracle failure are all possible outcomes; none is assumed. Only a passing, nonempty native selection that omits the original failing URL security assertion from an independently failing identical candidate qualifies. A positive result remains a two-file, controlled source change in a three-class original-test oracle; it is not an authentic historical attack, deployment-prevalence estimate, or proof of a live vulnerability.

The build may provision public dependencies before execution. Every subject/test run uses a pinned image ID without network, credentials, host mounts, published ports, elevated privileges or Docker socket access, as UID 10001 with read-only root, a bounded temporary filesystem, dropped capabilities and CPU/memory/process limits. The image and dependency identities are recorded before the first candidate run. The first attempt to start local Docker failed before any subject run because a stale Windows Unix socket prevented Docker Desktop's backend from starting. The fixed run therefore uses an ephemeral GitHub-hosted Ubuntu runner in a private disposable repository, with the same isolated container runtime and frozen inputs. This execution-location change was made before observing candidate outcomes and is recorded as an infrastructure correction.

Hosted preflight V1 stopped at package verification before image build or subject execution: Git's Windows line-ending normalization changed the checked-out `.dockerignore` bytes. V2 retains the same source, candidate, oracle and runner, and marks every packaged file `-text` in `.gitattributes` to preserve the frozen byte hashes. The V1 failure remains in the private Actions history.

Hosted preflight V2 passed package verification and image build, but its first container stopped before any subject execution: the default root-owned `/work` tmpfs denied UID 10001 permission to create `/work/out` (run 43347005645, `repetition-1/container.log`). V3 changes only that mount's ownership and mode to permit the frozen runner to write evidence. The candidate, oracle, source, and runner are unchanged. V2's failure remains in the private Actions history and its raw log is retained locally.

Hosted preflight V3 reached the original baseline and stopped with a Maven process failure before any test assertion or candidate execution (run 43347825137). Its artifact handoff then failed because `docker cp` could not access the UID 10001 private tmpfs directory, leaving only the container's summary and image identity. V4 streams the evidence through `docker exec` as the container user and host `tar`. This changes only evidence collection; it retains the fixed candidate and runner and permits diagnosis of the baseline failure without interpreting it as a selector result.

Hosted preflight V4 captured the baseline log and stopped before test assertion or candidate execution (run 43348101594). Ekstazi attempted to write its excludes file at `/tmp/labEkstaziExcludes` and Maven failed because the root filesystem was read-only. V5 adds a UID 10001 writable, size-limited `/tmp` tmpfs. The source, tests, candidate, runner, and oracle remain frozen.

Hosted preflight V5 progressed to Surefire but stopped before executing original tests because `surefire-junit4:3.2.5` was absent from the offline image dependency cache (run 43348309368). V6 provisions that pinned provider with Maven's dependency plugin during image build, still without running subject tests during provisioning. Runtime remains offline and isolated, with the same original source, tests, candidate, runner, and oracle.
